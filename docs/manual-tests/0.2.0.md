# Roteiro manual — 0.2.0 (Windows e macOS)

O CI já verifica build, testes, instalação silenciosa, `--version` e `--selftest`. Este roteiro cobre o que só se vê à mão: janela, retomada no terminal, avisos do sistema e o watcher com o seu histórico real. Use os arquivos do pre-release `v0.2.0-rc.N` (GitHub Releases) e marque cada item. Registre o resultado (e prints de qualquer falha) na issue #14.

Antes: confira os arquivos com `sha256sum -c SHA256SUMS --ignore-missing` (no Windows, `certutil -hashfile <arquivo> SHA256` e compare com o `SHA256SUMS`).

## Windows 10/11

**Instalação**
- [ ] Rodar `SessionFlow-X-windows-amd64-setup.exe`: aparece o SmartScreen; *Mais informações* → *Executar assim mesmo* funciona.
- [ ] O instalador **não** pede administrador (sem UAC) e instala em `%LOCALAPPDATA%\Programs\SessionFlow`.
- [ ] Atalhos no Menu Iniciar e na área de trabalho abrem o app.
- [ ] *Configurações → Aplicativos* lista "SessionFlow" com a versão certa.

**Uso**
- [ ] A janela abre (WebView2), tema e fontes normais.
- [ ] Os agentes instalados aparecem como detectados (Claude Code em `%USERPROFILE%\.claude`, Codex em `%USERPROFILE%\.codex`, OpenCode em `%USERPROFILE%\.local\share\opencode`).
- [ ] As sessões são indexadas; projetos aparecem com o caminho `C:\...` certo (inclusive com espaço ou acento, se houver).
- [ ] Busca encontra texto e abre a conversa no trecho.
- [ ] Analytics (Consumo, Custos, Padrões) abre sem erro.
- [ ] Abrir o app de novo traz a janela existente para a frente (sem segunda instância).
- [ ] Anotar onde ficou a CLI de cada agente (`where claude`, `where codex`, `where opencode`) — ajuda a completar `docs/PROVIDERS.md`.

**Retomada**
- [ ] Com o Windows Terminal: *Retomar no terminal* abre uma aba nova no diretório do projeto, com a sessão carregada.
- [ ] Configurações mostram o Windows Terminal detectado (`…\WindowsApps\wt.exe`), não "console".
- [ ] Sem o Windows Terminal (ou configurando um caminho inexistente e voltando ao padrão): abre numa janela de console, que mostra a tela do agente e aceita digitação.
- [ ] CLI instalada pelo npm (`.cmd`): o botão vira *Copiar comando*, com a explicação; o comando copiado (`& 'C:\…\claude.cmd' --resume …`) funciona colado no PowerShell.
- [ ] Fechar o SessionFlow não fecha o terminal da sessão retomada.

**Portátil e remoção**
- [ ] O `.zip` portátil extraído abre e usa os mesmos dados da versão instalada.
- [ ] Desinstalar remove o programa; `%LOCALAPPDATA%\SessionFlow` (dados) e os históricos dos agentes continuam lá.

## macOS 13+ (Intel e/ou Apple Silicon)

**Instalação**
- [ ] Abrir o `.dmg` e arrastar para *Aplicativos*.
- [ ] Primeira abertura bloqueada pelo Gatekeeper; botão direito → *Abrir* → *Abrir* funciona (ou `xattr -dr com.apple.quarantine /Applications/SessionFlow.app`).
- [ ] *Sobre* / Finder mostram a versão certa.

**Uso**
- [ ] Janela, detecção dos agentes (`~/.claude`, `~/.codex`, `~/.local/share/opencode`), indexação, busca, viewer e Analytics funcionam.
- [ ] Segunda abertura traz a janela existente.
- [ ] Anotar `which claude codex opencode`.

**Retomada**
- [ ] Com kitty, WezTerm ou Alacritty instalado: *Retomar no terminal* abre a sessão no diretório do projeto.
- [ ] App aberto pelo Finder (não pelo terminal), com uma CLI instalada pelo npm (Codex ou OpenCode): a retomada abre a sessão (sem "env: node: No such file or directory").
- [ ] Com Ghostty (se instalado e for o único): anotar se abre janela nova.
- [ ] Só com o Terminal.app: o botão vira *Copiar comando*, com a explicação.

**Watcher (histórico real)**
- [ ] Com o app aberto e indexado, rodar `lsof -p $(pgrep -f SessionFlow.app/Contents/MacOS/sessionflow) | wc -l` e anotar.
- [ ] Rodar `ulimit -n` e `launchctl limit maxfiles` e anotar.
- [ ] No log (`~/Library/Logs/SessionFlow/sessionflow.log`), procurar "pasta não monitorada": anotar se apareceu (watcher degradado; a reconciliação de 1 min cobre).
- [ ] Mandar uma mensagem num agente: a sessão atualiza no SessionFlow (em segundos com o watcher; em até 1 min se degradado).

## Resultado

Com todos os itens marcados (ou as falhas registradas e aceitas na issue #14), o mantenedor dá o OK e a tag `v0.2.0` é criada.
